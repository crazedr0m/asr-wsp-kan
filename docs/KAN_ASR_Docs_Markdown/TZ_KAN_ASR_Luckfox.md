# Техническое задание (ТЗ)
## Система автоматического распознавания речи (ASR) на базе KAN без сплайнов с портированием на Rockchip NPU

> **Краткое резюме проекта:** Разработка компактной акустической модели распознавания речи на базе сетей Колмогорова–Арнольда (KAN) без использования B-сплайнов (FastKAN / ChebyKAN / MoE-KAN) на чистом PyTorch без сторонних KAN-библиотек, с последующей оптимизацией под кастомные CUDA-ядра, дообучением через Telegram-бота (Human-in-the-Loop) и портированием инференса на NPU платы Luckfox Pico Plus (Rockchip RV1103).

---

### 1. Цели и задачи проекта

1. **Архитектура без сплайнов:** Реализовать слои KAN на базе радиально-базисных функций (FastKAN / Гауссианы) и/или полиномов Чебышёва (ChebyKAN), а также мягкую смесь экспертов (Soft-MoE-KAN), с использованием исключительно стандартных матричных и сверточных операций (`Conv2d`, `MatMul`, `Exp`, `Tanh`, `SiLU`).
2. **Отказ от готовых KAN-библиотек:** Весь код слоев модели должен быть написан на чистом PyTorch для прозрачного переноса вычислений в кастомные C++/CUDA-ядра и компиляции в формат RKNN.
3. **Разделение контуров обучения и инференса:**
   - **Контур обучения, генерации данных и дообучения:** ПК с GPU NVIDIA RTX 3060 (12 ГБ) и GTX 1050 Ti (4 ГБ).
   - **Контур целевого инференса (Edge):** Одноплатный компьютер Luckfox Pico Plus (RV1103) с аппаратным NPU.
4. **Пайплайн данных и Active Learning:** Обеспечить генерацию синтетического датасета (TTS + аугментации) и разработать Telegram-бота на чистом `asyncio` + `aiohttp` для сбора реальных голосовых сообщений, их валидации пользователем и автоматического дообучения модели.

---

### 2. Аппаратные требования и ограничения

| Компонент | Характеристики | Назначение и ограничения |
| :--- | :--- | :--- |
| **Luckfox Pico Plus** | SoC Rockchip RV1103 (ARM Cortex-A7), 64 МБ DDR2 RAM, NPU 0.5 TOPS (INT4/INT8/INT16) | Только инференс. Вес модели `.rknn` не более 1.5–4 МБ. Пик активаций — до 8–10 МБ. Запуск строго на C++ (`librknnrt.so`), без Python на плате. Стриминг окнами по 1–2 сек. |
| **NVIDIA RTX 3060** | 12 ГБ VRAM, архитектура Ampere (Tensor Cores) | Основное обучение модели в смешанной точности `bfloat16`, работа Telegram-бота и фоновое дообучение (Fine-tuning). |
| **NVIDIA GTX 1050 Ti** | 4 ГБ VRAM, архитектура Pascal (без Tensor Cores) | Параллельная генерация синтетического аудиодатасета (TTS), аугментация, валидация и тестирование. Обучение строго в `FP32`. |

### 3. Требования к архитектуре нейросети (`TinyKAN_ASR`)

1. **Входные данные:** Лог-мел-спектрограмма (40 мел-бинов, шаг окна 10 мс), представленная как 4D-тензор формы `[Batch, 40, 1, Time]`.
2. **Акустический энкодер:** Блоки Depthwise Separable сверток, реализованные через `nn.Conv2d` с ядром `(1, K)` и `stride=(1, 2)` для 4-кратного сжатия временной оси (шаг 40 мс на выходе) и 100% аппаратной совместимости с Rockchip NPU.
3. **Блоки KAN (`FastKANConv1x1` / `PureChebyKANLayer` / `NPUFriendlyMoEKAN`):**
   - **Вычисление базиса:** для FastKAN — $\phi(x) = \exp\left(-\left(\frac{x - g}{\Delta}\right)^2\right)$ на фиксированной сетке $g \in [-2.0, 2.0]$ ($N_{\text{grids}} = 6 \dots 8$), объединенное с базовой веткой `SiLU` + `Conv2d 1x1`.
   - **Нормализация:** обязательное наличие `BatchNorm2d` перед слоями KAN для удержания активаций в рабочем диапазоне при квантовании в `INT8`.
   - **Отсутствие динамического ветвления** (`if/else`, `TopK`) в MoE — использование взвешенной суммы по всем 2–3 экспертам (`Softmax`).
4. **Выходной слой и функция потерь:** `nn.Conv2d(128, vocab_size, kernel_size=1)` (35 токенов: русский алфавит + пробел + `blank`), обучение с CTC Loss (Connectionist Temporal Classification).

---

### 4. Требования к датасету и Telegram-боту

1. **Базовый и синтетический датасеты:**
   - **Открытые корпуса:** Golos, Common Voice, Russian Open STT (для русского языка) / LibriSpeech (для английского).
   - **Генерация синтетики:** локальный TTS (Piper TTS / Silero TTS) по текстовым словарям + наложение шумов (MUSAN, белый/розовый шум), реверберации, искажений кодеков (OGG/MP3) и сдвига скорости/тона.
2. **Telegram-бот (Human-in-the-Loop):**
   - **Стек:** чистый Python (`asyncio`, `aiohttp`, системный вызов `ffmpeg` для декодирования `.ogg` в PCM 16 кГц моно) без тяжелых фреймворков.
   - **Логика:** прием голосового сообщения $\rightarrow$ распознавание текущей моделью $\rightarrow$ отправка текста пользователю с кнопками подтверждения (`Верно` / `Исправить`) $\rightarrow$ сохранение пары `(audio.wav, text)` в базу.
   - **Дообучение:** запуск при накоплении батча новых данных (например, 64–100 записей). Смешивание 70% новых примеров + 30% базового датасета (защита от катастрофического забывания), низкий learning rate ($10^{-5} \dots 5 \cdot 10^{-5}$), обновление весов только при снижении метрики WER на валидации.

---

### 5. Требования к портированию (CUDA и RKNN)

1. **CUDA-оптимизация:** Вынесение вычисления RBF/Чебышёв-базиса в отдельную функцию для последующей замены на C++/CUDA-расширение (`torch.utils.cpp_extension`) с объединением (`fusion`) операций вычитания сетки, возведения в квадрат, экспоненты и матричного умножения в регистрах GPU.
2. **Квантование и конвертация в RKNN:** Экспорт в ONNX (opset 12–16), подготовка калибровочной выборки из 100–200 реальных спектрограмм (`.npy`) и сборка `.rknn` модели через `rknn-toolkit2` с включенным квантованием `INT8` (`target_platform='rv1103'`).
