Как работает симулятор NPU на ПК

• Официальный эмулятор в RKNN-Toolkit2. В состав Python-библиотеки RKNN-Toolkit2 встроен программный симулятор NPU. Он позволяет конвертировать модели (из ONNX, PyTorch, TensorFlow) в формат .rknn, проверять точность после квантования (INT8/INT4) и прогонять инференс прямо на ПК без подключения самой платы. [1] (https://wiki.luckfox.com/Luckfox-Pico-Ultra/RKNN/), [2] (https://docs.banana-pi.org/en/BPI-CM5_Pro/BananaPi_BPI-CM5_Pro/Rockchip_RKNN_Guide), [3] (https://habr.com/ru/companies/ods/articles/928974/), [4] (https://github.com/airockchip/rknn-toolkit2)
• Ограничение по железу (GPU vs CPU). Симулятор NPU в составе RKNN-Toolkit2 работает только на центральном процессоре (CPU) архитектуры x86_64 под управлением Linux (рекомендуется Ubuntu 20.04 или 22.04). Использовать видеокарты GTX 1050 или RTX 3060 для ускорения именно эмуляции самого NPU не получится, так как проприетарный симулятор Rockchip не поддерживает CUDA. [1] (https://github.com/rockchip-linux/rknn-toolkit2), [2] (https://habr.com/ru/companies/ods/articles/928974/)
• Где пригодятся GTX 1050 / RTX 3060. Видеокарты NVIDIA на ПК можно эффективно задействовать на подготовительных этапах: для обучения нейросетей, их дообучения с учетом квантования (QAT) или быстрого прогона исходных ONNX-моделей через ONNX Runtime / TensorRT до этапа конвертации в формат Rockchip.

Если какой-то слой не поддерживается, симулятор выдаст предупреждение или перенесет его расчет на CPU.

3. Готовый скрипт для конвертации и запуска симулятора

Сохраните этот код как simulate_rv1103.py и адаптируйте под размерность входов вашей сети:
python
import numpy as np
from rknn.api import RKNN

ONNX_MODEL = 'my_custom_model.onnx'
RKNN_MODEL = 'my_custom_model_rv1103.rknn'
DATASET_PATH = './dataset.txt'

if __name__ == '__main__':
    # 1. Инициализация объекта RKNN (verbose=True покажет подробный лог компиляции слоев)
    rknn = RKNN(verbose=True)

    # 2. Конфигурация под RV1103 (Luckfox Pico Plus)
    # Укажите mean_values и std_values, если ваша модель требует нормализации входа
    print('--> Config model')
    rknn.config(
        mean_values=[[0, 0, 0]],
        std_values=[[255, 255, 255]],
        target_platform='rv1103',
        quantized_dtype='asymmetric_quantized-8' # стандартный INT8 для RV1103
    )

    # 3. Загрузка вашей ONNX модели
    print('--> Loading model')
    ret = rknn.load_onnx(model=ONNX_MODEL)
    if ret != 0:
        print('Ошибка загрузки ONNX модели!')
        exit(ret)

    # 4. Сборка и квантование модели (компиляция под архитектуру NPU)
    print('--> Building model')
    ret = rknn.build(do_quantization=True, dataset=DATASET_PATH)
    if ret != 0:
        print('Ошибка сборки модели!')
        exit(ret)

    # 5. Экспорт готового файла для переноса на плату Luckfox
    print('--> Export rknn model')
    ret = rknn.export_rknn(RKNN_MODEL)
    if ret != 0:
        print('Ошибка экспорта!')
        exit(ret)

    # 6. Запуск симулятора NPU на ПК (target=None включает эмулятор на CPU)
    print('--> Init runtime environment (Simulator)')
    ret = rknn.init_runtime(target=None)
    if ret != 0:
        print('Ошибка инициализации симулятора!')
        exit(ret)

    # 7. Тестовый прогон (замените форму (1, 224, 224, 3) на размерность вашего входа)
    # Важно: симулятор ожидает данные в формате NHWC и типе uint8 (если заданы mean/std)
    dummy_input = np.random.randint(0, 256, size=(1, 224, 224, 3), dtype=np.uint8)

    print('--> Running inference on simulator')
    outputs = rknn.inference(inputs=[dummy_input], data_format=['nhwc'])

    print('Успешно! Выходной тензор:', outputs[0].shape)
    print('Пример значений:', outputs[0].flatten()[:10])

    # Освобождение ресурсов
    rknn.release()
Используйте код с осторожностью.

Полезные советы при отладке своей архитектуры

• Проверка потери точности после INT8. В RKNN-Toolkit2 есть встроенный инструмент rknn.accuracy_analysis(inputs=['test_sample.jpg']). Он прогоняет один и тот же вход через исходный ONNX (float32) и через сэмулированный NPU (int8), а затем выдает отчет о косинусном сходстве по каждому слою. Это поможет сразу найти слой, на котором "сыпется" точность после квантования.
• Формат данных (NHWC vs NCHW). В PyTorch тензоры обычно имеют формат NCHW (Batch, Channels, Height, Width), но сам NPU Rockchip нативно работает с NHWC (Batch, Height, Width, Channels). При подаче данных в rknn.inference() удобнее сразу передавать массив в NHWC (как обычное изображение из OpenCV/NumPy).
• Профилирование памяти. На самой плате Luckfox Pico Plus всего 64 МБ оперативной памяти (из которых часть занята Linux и буферами камеры). В симуляторе на ПК вы можете вызвать rknn.eval_memory() после инициализации рантайма, чтобы заранее увидеть, сколько мегабайт весов и активаций потребует ваша модель и поместится ли она в память платы.

1. Куда девать CUDA-ядра и как портировать модель

NPU в чипе RV1103 — это специализированный матричный ускоритель. Он не понимает код CUDA и работает только со стандартным графом нейросети.
• Обучение на GPU, инференс на NPU. Ваши видеокарты GTX 1050 / RTX 3060 нужны только для быстрого обучения модели в PyTorch на Ubuntu. Перед экспортом модель нужно перевести на CPU (model.eval().cpu()).
• Ограничение кастомных CUDA-ядер. Если вы написали собственные низкоуровневые ядра на C++/CUDA для каких-то нестандартных слоев, NPU не сможет их выполнить. Граф модели должен состоять из стандартных слоев PyTorch (Conv1d, Conv2d, Linear, ReLU, BatchNorm, LSTM/GRU), которые корректно экспортируются в ONNX.
• Препроцессинг звука (STFT / MFCC). Не вшивайте быстрое преобразование Фурье (STFT) или расчет мел-спектрограмм внутрь самой нейросети. NPU плохо переваривает комплексные числа и операции спектрального анализа. Считайте спектрограмму на CPU (на ПК через torchaudio/librosa, а на самой плате Luckfox — на C/C++ через легкие библиотеки вроде kissfft), а на вход NPU подавайте уже готовую двумерную матрицу (как картинку).

2. Архитектурные нюансы для звука на RV1103

• Замените 1D-свертки на 2D. NPU RV1103 аппаратно оптимизирован под 2D-свертки (Conv2d). Одномерные свертки (Conv1d), которые часто используют для аудио, либо работают медленно, либо разворачиваются в 2D с лишними накладными расходами. Даже если вы работаете с сырым аудиосигналом или 1D-признаками, на этапе архитектуры лучше представить вход как 2D-тензор (Batch, Channels, Height, 1) и использовать Conv2d с ядром (K, 1).
• Осторожно с RNN / Transformer. Если в распознавании используется рекуррентная часть (LSTM, GRU) или Attention, проверьте в симуляторе, какие слои ушли на NPU, а какие упали на CPU. В логах RKNN-Toolkit2 при сборке (rknn.build) смотрите таблицу операторов: напротив каждого слоя должно стоять NPU.

Какую задачу решает модель (например, активация по ключевому слову / KWS, классификация звуков или потоковое распознавание речи) и какие слои используются внутри (свертки, LSTM, трансформеры)? Я подскажу, как избежать потери точности при сжатии до INT8.

Да, использовать слои KAN (Kolmogorov-Arnold Networks) можно, но только при условии, что они реализованы на базе стандартных матричных операций PyTorch, без кастомных CUDA-расширений.
Аппаратный NPU в RV1103 ничего не знает о концепции KAN, но он умеет быстро умножать матрицы (MatMul / Conv2d) и считать базовые поэлементные функции активации. Поэтому возможность запуска зависит от того, какой именно вариант KAN вы используете.

Какие реализации KAN заработают на NPU

• Вариант 1. FastKAN / RBF-KAN / FourierKAN (Рекомендуемый). В этих модификациях B-сплайны заменяются на радиально-базисные функции (гауссианы), ряды Фурье или полиномы Чебышёва. При экспорте в ONNX такой слой раскладывается в обычные линейные слои (Linear), поэлементное вычитание, возведение в квадрат, экспоненту (Exp) или Sin/Cos. NPU RV1103 легко переварит такой граф, хотя сложные активации могут частично уйти на CPU.
• Вариант 2. Classic B-spline KAN (pykan / efficient-kan). В классической реализации вычисление B-сплайнов требует сложной индексации по сетке (grid), рекурсивного построения полиномов и нестандартных тензорных перестановок (einsum). При конвертации в ONNX и сборке в RKNN-Toolkit2 большинство этих операций либо вызовут ошибку компиляции, либо полностью упадут на слабый процессор платы (ARM Cortex-A7), убив весь смысл использования NPU.

Как подготовить KAN-модель к эмуляции и запуску на RV1103

1. Переведите вычисления в линейную форму. Используйте архитектуру вроде FastKAN или ChebyKAN (на полиномах Чебышёва), где базисные функции считаются через простые арифметические операции, а итоговое взвешивание происходит через стандартный torch.nn.Linear или Conv2d с ядром 1x1.
2. Откажитесь от кастомных CUDA-ядер на этапе экспорта. Если для ускорения обучения на GTX 1050 / RTX 3060 вы используете библиотеку с написанными на C++/CUDA кернелами для сплайнов, перед torch.onnx.export замените эти модули на их чистый аналог на PyTorch с теми же весами.
3. Замените einsum на matmul. В многих репозиториях KAN умножение базисов на веса написано через torch.einsum. Парсер ONNX в RKNN-Toolkit2 часто спотыкается об einsum. Перепишите такие места через стандартные reshape + torch.matmul или Conv2d.
4. Будьте осторожны с квантованием (INT8). KAN-сети очень чувствительны к точности представления сплайнов и базисных функций. При сжатии до INT8 мелкие колебания кривых могут «схлопнуться» в ступеньки. После сборки в симуляторе обязательно прогоните rknn.accuracy_analysis(), чтобы убедиться, что квантование не разрушило логику слоя.

Как проверить в симуляторе

Сконвертируйте вашу KAN-модель в ONNX и прогоните через rknn.build() с флагом verbose=True. В консоли появится таблица распределения операторов (Target column). Если напротив основных весовых операций стоит NPU, а на CPU вынесены только единичные активации — модель успешно заработает на Luckfox Pico Plus.
